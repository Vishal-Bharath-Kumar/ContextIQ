## Story

**As a** DevOps/SRE,
**I want** every AI context request to produce a distributed trace visible in Jaeger,
**So that** I can identify performance bottlenecks across the multi-agent pipeline.

## Acceptance Criteria

- [ ] Every inbound MCP tool call creates a root OTel span with `request_id` as trace ID
- [ ] Each pipeline node (Intent, Retrieval, Compression, Governance, Routing) creates a child span
- [ ] Each connector `fetch()` call creates a separate child span with connector ID label
- [ ] Spans include relevant attributes: `intent_type`, `token_count`, `model_id`, `connector_id`
- [ ] Traces are exported to Jaeger via OTLP gRPC exporter
- [ ] Jaeger trace for any request is retrievable within 5 s of completion by `request_id`
- [ ] OTel SDK is configured as a cross-cutting concern (not per-service instrumentation)

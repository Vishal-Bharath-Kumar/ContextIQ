## Story

**As a** software developer,
**I want** ContextIQ to return the best available context even when one or more connectors fail,
**So that** my AI assistant is never completely blocked by a single unavailable source.

## Acceptance Criteria

- [ ] If one connector fails (exception or timeout), its result is omitted and others continue
- [ ] Partial response includes a `degraded_sources` field listing failed connector IDs
- [ ] Response is still returned to the AI assistant with HTTP 200 and partial context payload
- [ ] Platform health metric `connector_failure_count{connector_id}` is incremented
- [ ] Repeated failures from the same connector trigger circuit-breaker open state after 5 failures in 60 s
- [ ] Circuit-breaker state is logged and observable in Grafana

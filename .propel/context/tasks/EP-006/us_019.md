## Story

**As a** software developer,
**I want** ContextIQ to automatically route my request to the most cost-effective model that meets the quality requirements for my intent,
**So that** I get accurate responses without unnecessarily consuming expensive model tokens.

## Acceptance Criteria

- [ ] Router evaluates candidates by computing a weighted score: quality_weight × quality_score + cost_weight × (1/cost) + latency_weight × (1/latency)
- [ ] Routing weights are configurable per intent type (e.g., "code-gen" prioritizes quality; "summarization" prioritizes cost)
- [ ] Selected model ID and routing score are stored in execution state
- [ ] Routing decision is logged and emitted to Langfuse with model ID and reasoning
- [ ] Routing latency is < 50 ms (selection from pre-scored candidate list in Redis)
- [ ] Selected model is invoked via LiteLLM unified API

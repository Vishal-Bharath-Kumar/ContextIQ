## Story

**As a** platform engineer,
**I want** stateless ContextIQ services (MCP Gateway, Agent Worker, Indexing Service) to scale horizontally based on CPU and custom metrics,
**So that** the platform handles traffic spikes without manual intervention.

## Acceptance Criteria

- [ ] HPA is configured for: `contextiq-gateway` (min 2, max 10), `contextiq-agent-worker` (min 2, max 20), `contextiq-indexing` (min 1, max 5)
- [ ] HPA for `contextiq-agent-worker` scales on custom metric `contextiq_active_requests` via Prometheus Adapter
- [ ] HPA for `contextiq-gateway` scales on CPU utilization (target 60%)
- [ ] Scale-up triggers within 30 s of metric threshold breach; scale-down has a 5-minute stabilization window
- [ ] Minimum 2 replicas of the MCP Gateway are always running (PodDisruptionBudget)
- [ ] HPA configuration is included in Helm chart values and tested in staging environment

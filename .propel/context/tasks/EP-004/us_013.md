## Story

**As a** platform engineer,
**I want** repeated or semantically similar context queries to be served from Redis cache,
**So that** average response latency is reduced and load on vector and keyword stores is minimized.

## Acceptance Criteria

- [ ] Cache key is a deterministic hash of (query embedding, source list, token budget)
- [ ] Cache hit returns results in < 50 ms
- [ ] Cache TTL is configurable per source type (default: code = 5 min, docs = 30 min)
- [ ] Cache miss triggers full hybrid search; result is written to cache on success
- [ ] Cache hit rate is exposed as Prometheus metric `context_cache_hit_ratio`
- [ ] Cache is invalidated per source when a new sync event is emitted for that source

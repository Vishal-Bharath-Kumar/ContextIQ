## Story

**As a** platform engineer,
**I want** the knowledge graph to be updated incrementally whenever a knowledge source is synced,
**So that** graph relationships always reflect the current state of the enterprise without requiring full re-indexing.

## Acceptance Criteria

- [ ] Graph updater consumes `knowledge.source.synced` and `knowledge.chunk.indexed` Kafka events
- [ ] New entities and relationships inferred from changed chunks are upserted into Neo4j
- [ ] Relationships for deleted entities are removed (tombstone pattern via deletion events)
- [ ] Incremental update completes within 5 s per sync batch of 500 chunks
- [ ] Stale relationships (no update within configurable TTL, default 30 days) are expired
- [ ] Graph update events are emitted to Kafka topic `knowledge.graph.updated` for downstream consumers

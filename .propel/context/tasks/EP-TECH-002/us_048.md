## Story

**As a** security officer,
**I want** all inter-service and external traffic to use TLS 1.3, and all data at rest to be encrypted,
**So that** the platform meets enterprise security standards and protects sensitive AI context data.

## Acceptance Criteria

- [ ] cert-manager is deployed and issues TLS certificates from an internal CA (or Let's Encrypt for edge)
- [ ] All Kubernetes Ingress resources terminate TLS with certificates issued by cert-manager
- [ ] mTLS is enforced for all inter-service communication within the cluster (Istio or cert-manager + SPIFFE)
- [ ] TLS 1.2 is disabled; only TLS 1.3 is accepted at all ingress points
- [ ] PostgreSQL, Qdrant, Neo4j, Redis, and MinIO are configured with encryption at rest (storage class encryption or application-level AES-256)
- [ ] `kubectl exec` port-forwarding is restricted via admission webhook in production
- [ ] Annual TLS certificate rotation is automated via cert-manager `CertificateRequest` renewals

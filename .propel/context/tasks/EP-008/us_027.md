## Story

**As a** platform engineer,
**I want** the indexing pipeline to generate embeddings for every synced chunk and store them in Qdrant,
**So that** the Retrieval Engine can perform semantic vector search against enterprise content.

## Acceptance Criteria

- [ ] Indexing service consumes `knowledge.source.synced` Kafka events
- [ ] Each document chunk is embedded using the configured embedding model (default: `text-embedding-3-small`)
- [ ] Embeddings are stored in Qdrant in a collection named `<source_id>_<tenant_id>`
- [ ] Document content and metadata are stored in OpenSearch for BM25 keyword search
- [ ] PostgreSQL is updated with chunk metadata: `chunk_id`, `source_id`, `embedding_model`, `token_count`, `indexed_at`
- [ ] Indexing throughput ≥ 1 000 chunks/min for batch sync operations
- [ ] Stale embeddings from deleted documents are removed within 5 minutes of deletion event

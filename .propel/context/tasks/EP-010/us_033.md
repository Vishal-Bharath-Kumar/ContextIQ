## Story

**As a** security officer,
**I want** to create, update, and version governance policies through the Admin API,
**So that** I can evolve access control rules without requiring a platform deployment.

## Acceptance Criteria

- [ ] Admin API `POST /v1/policies` accepts a Rego policy body with `name`, `description`, and `version`
- [ ] New policy versions are stored in PostgreSQL; previous versions are retained for rollback
- [ ] `POST /v1/policies/{id}/activate` promotes a policy version to active; triggers OPA bundle refresh
- [ ] Policy rollback via `POST /v1/policies/{id}/rollback?version=N` restores a previous version
- [ ] Policy author and activation timestamp are recorded for audit log
- [ ] Attempting to activate a syntactically invalid Rego policy returns HTTP 422 with OPA parse error

## Story

**As a** platform engineer,
**I want** the PostgreSQL schema to be deployed and managed via Alembic migrations,
**So that** database schema changes are version-controlled, reproducible, and applied automatically on deployment.

## Acceptance Criteria

- [ ] PostgreSQL 15 is deployed as a StatefulSet with a persistent volume and automated backup (daily, 30-day retention)
- [ ] Alembic migration scripts cover all core tables: `connector_config`, `knowledge_source`, `knowledge_chunk`, `model_registry`, `policy`, `audit_log`, `execution_trace_index`, `sync_job`
- [ ] `alembic upgrade head` is executed as a Kubernetes Job on every deployment before pods start
- [ ] Migration failures roll back automatically and surface as a pod startup failure with descriptive logs
- [ ] PostgreSQL is configured with: connection pooling via PgBouncer, max 200 connections, 99.9% uptime target
- [ ] Read replicas are enabled for reporting queries (audit log, cost analytics)

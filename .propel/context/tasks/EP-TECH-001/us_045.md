## Story

**As a** platform engineer,
**I want** all ContextIQ services deployed to a Kubernetes cluster with defined namespaces, resource quotas, and network policies,
**So that** the platform is production-grade, tenant-isolated, and securely networked from day one.

## Acceptance Criteria

- [ ] Seven namespaces are created: `contextiq-data`, `contextiq-agents`, `contextiq-gateway`, `contextiq-admin`, `contextiq-observability`, `contextiq-security`, `contextiq-infra`
- [ ] Helm charts for each service are parameterized for dev / staging / production environments
- [ ] `ResourceQuota` and `LimitRange` objects are applied per namespace
- [ ] `NetworkPolicy` objects enforce default-deny + explicit allow rules between namespaces
- [ ] All services pass `kubectl rollout status` after initial deployment
- [ ] Platform-level readiness check: `GET /healthz` on each service returns HTTP 200 before traffic is served
- [ ] ArgoCD is configured to sync all Helm releases from the Git repository

# MCP Response Schemas

This document describes the JSON schemas for structured MCP `tools/call` response payloads returned by the ContextIQ Gateway.

## `ClarificationNeededResponse`

Returned when the agent pipeline exits via the clarification path (low-confidence intent detection). The Gateway serialises this as a `TextContent` MCP result — **not** an `McpError` — so the IDE or LLM orchestrator can display the question to the user and route the reply through the `clarification_reply` tool.

### Source

`src/gateway/schemas/clarification_response.py`

### JSON Schema

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "ClarificationNeededResponse",
  "type": "object",
  "required": ["type", "question", "original_prompt", "session_id"],
  "properties": {
    "type": {
      "type": "string",
      "const": "clarification_needed",
      "description": "Discriminator field. Always 'clarification_needed'."
    },
    "question": {
      "type": "string",
      "description": "Targeted clarification question (≤ 50 words) generated by the clarification_node LLM chain."
    },
    "original_prompt": {
      "type": "string",
      "description": "The ambiguous user prompt that triggered clarification, echoed for client context."
    },
    "session_id": {
      "type": "string",
      "description": "The request_id / thread_id. The client must include this value in the subsequent clarification_reply tool call."
    },
    "clarification_round": {
      "type": "integer",
      "default": 0,
      "description": "Zero-based counter of how many clarification rounds have occurred. Clients may display this for UX feedback."
    }
  },
  "additionalProperties": false
}
```

### Example Payload

```json
{
  "type": "clarification_needed",
  "question": "Are you referring to the auth-service or the API gateway when you say 'the service'?",
  "original_prompt": "add retry logic to the service",
  "session_id": "e3f1a2b4-7c8d-4e5f-a6b7-c8d9e0f1a2b3",
  "clarification_round": 0
}
```

### MCP Wire Format

The Gateway wraps this payload in an MCP `TextContent` item:

```json
{
  "type": "text",
  "text": "{\"type\":\"clarification_needed\",\"question\":\"...\",\"original_prompt\":\"...\",\"session_id\":\"...\",\"clarification_round\":0}"
}
```

### Error vs. Clarification

| Condition | MCP result type | HTTP status |
|---|---|---|
| Successful tool execution | `TextContent` | 200 |
| Clarification needed (low confidence) | `TextContent` | 200 |
| Invalid tool name or arguments | `McpError` (`INVALID_PARAMS`) | 200 (MCP error envelope) |
| Agent Worker timeout / pipeline failure | `TextContent` (error shape) | 200 |

`McpError` is reserved for protocol-level failures. A clarification response is a valid, successful tool invocation result.

### Related

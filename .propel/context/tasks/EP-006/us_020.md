## Story

**As a** software developer,
**I want** my request to be automatically retried against a fallback model when the selected model is unavailable or returns an error,
**So that** my AI workflow is not interrupted by transient provider outages.

## Acceptance Criteria

- [ ] Router maintains an ordered fallback list per intent type
- [ ] When the primary model returns HTTP 5xx, 429, or timeout, the router retries with the next model in the fallback list
- [ ] Maximum of 3 fallback attempts before returning a structured failure response
- [ ] Fallback event is logged with primary model ID, error code, and fallback model ID
- [ ] Circuit-breaker opens for a provider after 5 consecutive failures within 60 s
- [ ] Fallback adds no more than 500 ms of additional latency per retry
